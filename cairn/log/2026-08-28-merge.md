# A collision is a key written twice

`tcal merge BASE LOCAL REMOTE OUTPUT` lands: the three-way merge run in process, its result projected as TOML, edited in `$EDITOR`, and written out only once the document parses. It is the program a sync tool hands three bodies to and takes one back from, and the piece it needed was small, since tCal already renders and parses the document.

The proposal said the merge was "a function it already links". It was not: tCal depends on calcard 0.3, and the merge lives in ical-rs, over a byte-faithful syntax tree calcard has no notion of. The bridge is narrow rather than a migration. `Merge::project` reads the three sides with `IcalCst::parse`, runs `IcalMerge`, serialises the merged tree back to iCalendar text, and hands that text to the existing calcard path, so the merged bytes are the source the projection reads and the source `apply` patches. No second writer, no second model, and calcard stays the reader it has always been.

## What landed

- **The verb** (capability `merge`), behind an opt-in `merge` cargo feature that `cli` pulls in, ical-rs narrowed to its `parser` feature and the module gated once at its declaration, so a consumer wanting only the projection links one iCalendar library as before. This matches tCard, which landed the same change in parallel; the error variants stay ungated, since neither names a type from the optional crate. Four positional paths in git mergetool order, base first, then the two divergent sides, then the output, so `merger = "tcal merge"` needs no configuration on the neverest side. `--speaks-for ADDRESS` is passed through as `right_speaks_for`, normalised to a `mailto:` URI first, since ical-rs compares it against the raw `ORGANIZER` value and an organiser editing their own meeting would otherwise be refused by a missing scheme. The reprompt loop the `edit` verb already had is now shared by both verbs (`edit_until_applied`), which is where the second call site earned the extraction.

  The local side is the merge's **right** side. That is the load-bearing mapping: authority is refused on right-side actions, and the edited side is the one an attendee may not use to rewrite the organiser's meeting. It follows that a collision no one settles keeps the remote value in the merged bytes, which the document then asks about.

- **A choice is duplicate keys.** A contested field is written once per side with the ancestor commented above, each live line naming its side. The forcing is TOML's own. The projected lines of each side are produced by the same `Field::lines` the projection uses, so a choice is spelled exactly as the document around it, hints excepted. A field that projects to several lines (a date and its zone, a duration, a recurrence) is contested whole: half of each side would be neither side's value.

- **Three settled reasons are header comments.** A removal against an update, a rule against an overriding instance, and a refusal for want of authority, each naming the block and key it landed on, wrapped into the projection's own header block. A fourth case joins them: a collision on something the projection does not model, where there is no key to write twice and the comment says which value was kept.

- **Nested collisions decompose.** The merge's component path is walked against the merged calcard calendar, `UID` then `RECURRENCE-ID` then sibling position, down to a `Spec` and a `Field`, which gives both the block address in the document and the key. An attendee is the one property projected as a table, so a contested attendee is contested key by key inside the one table it wrote; a repeated `[[event.attendee]]` header would be valid TOML and a second attendee.

- **The refusal names the property.** `Merged::apply` catches toml_edit's duplicate-key error, reads the key out of the error's span, and raises `TcalError::Undecided(key)` instead of `ParseToml`. The prompt then says which property is still undecided rather than showing a parse error at a column.

## Verification

- 61 tests green (59 lib, 1 fixture, 1 doctest), `cargo clippy --all-features --all-targets` clean, `cargo fmt`.
- The four cases the change is judged on are unit tests in `src/merge.rs`: an undecided document does not apply and names `summary`; deleting the remote line applies the local value; a rule against an instance keeps both changes, says so in a comment and parses as it stands; a refusal for want of authority leaves the start as the organiser's and says so in a comment. Two more pin the shape: one contested alarm stays one alarm with its other keys written once, and a removal against an update keeps the update and comments it.

## Not in scope

Component-type filters (`--event` and friends) are not offered on `merge`: the document is a whole calendar, and a filtered merge would hide collisions rather than settle them. No conflict vocabulary was added to the parse side, since an undecided document does not parse and there is nothing to read back.

Capabilities moved: `merge` (new).
